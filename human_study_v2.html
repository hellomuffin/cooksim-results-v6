真人研究第二批：模拟器验证与 human agent 审计

2026-09-23 · 31 位完成全程的参与者（404 局，其中 279 局有 assistant 陪同）· 对照 formal run v5 第一轮 2125 局模拟 · 数据：study_collected_v2/，脚本 study_collected_v2/tools/

这一页回答三个问题。E1：我们的哪一个指标（in-time success、efficiency、interaction quality）能复现参与者给三个 assistant 的排序；E2：参与者对模型的总体排序，与模拟器给同一批模型的排序是否一致；E3：模拟 cook（human agent）在动作、对话、犯错、听劝这几个维度上，与真人有多像——审计的设计与结果。所有数字来自同一份 tidy table 和同一个行为抽取器，页面由脚本生成。

数据与规则

收到 28 个压缩包，其中一个是 Drive 文件夹导出（含「Additional Participants」子目录）。同一台笔记本的文件夹里可以有多份 participants/<pid>.json（共用机器或重复上传），按记录里的 seed 去重后得到 36 份独立轨迹，31 份完成了三轮排序。协议与上一批相同：先独自玩 4 局（Phase 1，两道菜 × medium/hard 两张图），再由三个匿名 assistant（A/B/C）陪玩 9 局（Phase 2，三轮，每轮三个 assistant 各一局、各一道不同的菜；三轮构成 Latin square，每个 assistant 与每道菜各配一次），每轮结束排一次序。engine_rev 全部为 84e66a9f14。

沉默规则（用户，2026-09-23）。assistant 一句话都没说的局记为 invalid：该局在排序里的位置不计，但同一轮另外两局的相对顺序仍然有效。62 / 279 局（22%）触发了这条规则，按模型：Gemini 3.7 Flash 34/87、Gemini 3.1 Pro 11/69、Gemini 3 Flash 8/66、GPT-realtime 2.1 3/15、Gemini 3.1 Flash Live 3/12、GPT-5.5 2/18、GPT-5.4 mini 1/12。检查过记录：这些局里 assistant 有被正常调用（每局 10–17 次），每一次都输出 kind: silent——是模型自己选择不说话，不是 API 故障。剔除后剩 166 个有效有序对（原 279 个），来自 31 位参与者。

七个 assistant 分布在几种三人组合里：{Gemini 3 Flash, Gemini 3.1 Pro, Gemini 3.7 Flash} × 22；{Gemini 3.7 Flash, GPT-5.5, GPT-realtime 2.1} × 2；{Gemini 3.7 Flash, GPT-5.4 mini, GPT-realtime 2.1} × 2；{Gemini 3.1 Flash Live, Gemini 3.7 Flash, GPT-5.4 mini} × 1；{Gemini 3.1 Flash Live, GPT-5.5, GPT-realtime 2.1} × 1；{Gemini 3.1 Flash Live, GPT-5.4 mini, GPT-5.5} × 1；{Gemini 3.1 Pro, Gemini 3.7 Flash, GPT-5.5} × 1；{Gemini 3.1 Flash Live, Gemini 3.7 Flash, GPT-5.5} × 1。Gemini 3.7 Flash 出现在大多数组合里，是把各组合连成一张图的桥。

E1 · 我们的指标能否复现参与者的排序

一个 assistant 在一局里得到一个分数 s；参与者的一次排序 A>B>C 给出三个有序对。对一种打分方式，

agreement = (1/N) Σ有效对 [ 1(swinner > sloser) + ½·1(swinner = sloser) ]

0.5 是随机；同样的 166 对上随机分数的 95 分位 0.566、99 分位 0.596。区间是按参与者做的 bootstrap 95%。

时钟的裁定（用户，2026-09-23）：站着不动也算时间。study app 自带的 eval_human_v3 原来把 in-time 的时钟定义成「动作 tick」（站着不动的 tick 不算）；现已改为 benchmark 的墙钟定义 S = 1[won]·1[T ≤ 2·Tref]（真人局没有注入，allowance 为 0），TT、CC 同样按墙钟；本页所有 S/TT/E 都是这个定义。有 assistant 陪同的非沉默局：做成 94%，在 2×Tref 内做成 83%，1.5× 内 69%，1.25× 内 49%；墙钟 / Tref 的中位数 1.24、p75 1.60、p90 2.06。所以「大多数不在时限内」在 benchmark 的 2× cap 下不成立（83% 在时限内），要到 1.25× 才过半不在。

一个混淆。一轮里三个 assistant 各配一道不同的菜，参与者更偏爱抽到简单菜的那个：用「菜的 reference ticks 越小越好」这个与 assistant 无关的分数去预测排序，逐轮一致率 0.61（CI 0.54–0.68）。Latin square 让它在参与者层面抵消（每个 assistant 与每道菜各配一次）：以（参与者 × 模型对）为单位——人的偏好 = 三轮里 i 排在 j 前面的次数，指标 = i 各局均值 vs j 各局均值——71 个单位、30 人，这一层上「菜简单者优」降到 0.57（CI 0.45–0.70）。下表两列都给。

S 为什么不可能反映人的排序。S 是二值的，而两局里的人几乎总是都做成：36/166 对在 S 上不平（cap 1.5× 也只有 44 对），其余全是平局记 ½。在那 36 对不平的对里，人偏爱做成的那一局的比例是 0.47——就是说，即使把平局拿掉，「有 assistant A 时我做成了、有 B 时没做成」也不决定人对 A、B 的排序。收紧 cap 到 1.5× 或放宽到 3× 都不改变这一点（0.52 / 0.48）。

效率也不反映。TT（墙钟）0.53 / 参与者层 0.58；E 按人自己的问卷权重、只在做成的局上定义，0.47 / 0.53；把未做成记 0 也是 0.48。CC 单独 0.57 / 0.59——三者里唯一在参与者层面高出随机的是 CC，而它量的是 assistant 说话压在动作上的时间，与 assistant 的对错无关。

能反映的是 AQ，但没有一项超过 0.7。两 judge 平均的 AQ 逐轮 0.630（CI 0.56–0.70）、参与者层 0.641（CI 0.50–0.76）；上一批在 12 人上拟合出的 8·AQ + 7·CC = 0.73，在这 31 人上是 0.654 / 0.620——那个 0.73 是对 12 个人的过拟合。这批数据里唯一过 0.7 的是事后拟出来的 AQ − 0.1 × false alarms（0.699 / 0.690），而单独的「false alarm 越少越好」就有 0.672（CI 0.61–0.73）。真人对 assistant 的判断主要是一件事：它有没有错怪我。assistant 对真人发出的 491 次警告里 245 次（50%）是 false alarm，只有 41 次说对。

要让 S 和效率也反映人的评价，改的不是指标而是研究设计。在自由游玩里 assistant 改变不了结果——人自己就能做成（沉默局 90%），时间差是人自己的手速。S 与 E 要有区分度，需要 assistant 的话能左右结局的局：给真人也注入强制错误（像 benchmark 那样由 engine 接管一步），或者更紧的时限与更难的菜。这是下一批研究的设计问题，本页无法用现有数据补。

关于「这是不是 Elo」。参与者那一侧不是 Elo：Elo 是对按时间到来的对局做在线更新的近似；对局全在手上时直接拟合它的批量版本 Bradley–Terry。指标那一侧不需要排名模型——每局有一个绝对分数，问题只是它的大小顺序与人的顺序有多一致，所以用有序对一致率。

E3 · human agent 审计：一个抽象的保真测试

NeurIPS workshop 稿评估模拟 cook 用的是三条轴——persona fidelity（B）、instruction following（C）、control consistency（D）——各用 engine 内的 probe 测。有了真人数据，同一件事可以换成一个更强的问法：对每一条轴，模拟 cook 的行为是否与 31 位真人的行为在统计上不可区分。每条轴下面是若干 rubric item；每个 item 有一个真人目标值（真人各局的均值）和一个容差（真人个体之间的标准差——同一个量在人与人之间本来就差这么多，模拟 cook 落在这个范围内就算「像一个人」；没有个体 SD 的比例量用真人 95% CI 的半宽）：

pass(item) = 1[ |x̄sim − x̄human| ≤ SDbetween people(x) ] ，axis score = 通过的 item 占比

两侧的量都由同一段代码从逐 tick 世界状态读出；模拟侧遮掉 engine 接管的 tick 与注入窗口、剔除脚本化发言。对照：REAL assisted（217 局，assistant 开过口）vs SIM = formal run v5 第一轮（2125 局，18 个 assistant × 3 persona，同样的 10 个厨房）。

读法。模拟 cook 在 C · 指令跟随上最像人（0.75）：点名食材的拾取率、未点名的对照、反驳的比例都在真人的个体差异之内；唯一不过的是被正确警告后改正得比真人勤（0.66 vs 0.40）。A · 节奏一半像：首次用火、走动、并行度像；idle、熟食在火上的等待、整体墙钟（2.3× vs 1.4× 参考时间）不像——后两者是上一批已经指出、仍未修的引擎问题（执行器死 tick；先做完菜再拿盘）。E · 错误画像：真人自己会犯的错（放错顺序、放生的）模拟 cook 以同样的频率犯；模拟 cook 多出来的是让菜冒烟（0.30 vs 0.08 次/100 tick）和放菜谱外的东西（真人从不）。D · 对话最不像（0.36）：句长、问题的比例、「问在哪/该做什么」和「纠正 assistant」的占比都像人，但发言量差 40 倍、几乎每句都回、24% 的句子在播报自己的下一步；真人有而模拟没有的是打招呼、问策略、主动请求「好了叫我」。B · persona（0.50）：幅度上 persona 的极差大多没有超过真人的极差（除了发言量），但方向上 persona 拨盘造成的差异与真人按问卷分组的差异对不上——真人不同问卷组之间几乎没有行为差异，而 novice/expert 在 idle、首次用火、发言量上差一倍。要注意这一轴的对照是近似的：模拟的 skill/trust 是私有轴，问卷里没有对应项。

总分 0.49：模拟 cook 在「听不听劝」和「犯什么错」上已经像人，在「怎么说话」和「什么时候停下来」上还不像。

附录 · 逐项对照表

真人侧「改正」= app 判为 correct 的 flag 之后，对应的世界真值谓词在 30 tick 内消失；模拟侧 = 被正确 flag 的注入错误随后被 cook 放弃（engine 的 prevented）。两个定义不完全同构（模拟侧的错误是 engine 强推的、放弃要靠 assistant 说服；真人侧的错误是自己犯的），但方向一致：模拟 cook 比真人更听劝——novice 0.73、expert 0.53，真人 0.40。按错误类型，模拟 cook 对 mis_prep（138/178）、forget_next_step（107/146）几乎有劝必改，对 add_foreign（3/16）、misidentify（2/15）、omit_subgoal（4/13）几乎不改——这三种是「hard」接管，改不改由 engine 决定，不是 cook 的性格。

发现

F1 · 身体节奏：像的部分和不像的部分。第一次用火的 tick 真人 55、模拟 52——上一批「真人开局要摸索」的差距已经没有了（这批真人是第二、三轮的老手，模拟 baseline/expert 41/37，novice 80）。walk 占比 0.35 vs 0.32 也接近。不像的是 idle：真人 0.17，模拟 0.31（novice 0.42）；并行度真人 0.21、模拟 0.16。上一批的 F1（执行器每条命令吃一个死 tick）没有改，这仍是 idle 差距的主要来源。

F2 · 热源：模拟 cook 仍然让熟食等到冒烟。熟食在火上的等待真人 12.7 tick、模拟 26.9（tight pace 的冒烟线是 25）；注入窗口外自己冒烟的局，真人 29/217，模拟 1204/2125。表 6 用同一套谓词看 onset：smoking 每 100 tick 模拟 0.36 次、真人 0.09（独自时 0.15）。有意思的是 done-food-on-heat 的 onset 真人反而更多（0.91 vs 0.55）：真人也让菜熟在锅里，但很快就去舀（13 tick），模拟 cook 一放就是 27。上一批的 F2 原因（先把菜全做完、最后拿盘）仍在。

F8 · 真人跨局学习，模拟 cook 不学。真人独自四局的 in-time success 0.47 → 0.71 → 0.81 → 0.74；陪玩三轮 S 0.75 / 0.85 / 0.90，idle 0.21 / 0.16 / 0.15，发言 0.67 / 0.42 / 0.15 句/100t——越玩越熟、越玩越不说话。模拟 cook 每局从零开始，也没有「新手第一局」的状态；这批真人的 Phase 2 是熟手，所以对照模拟时 novice persona 反而是最不像的。

F9 · 结果层面还缺一个对照。真人独自做成率（S）四局均值 0.68，有 assistant 时 0.83；模拟侧所有局都带错误注入（≥ 半数是毁菜的），won 只有 31%，无法与真人比较「独自做成率」。需要一次 cook-only、无注入、无 assistant 的干净 run（10 个厨房 × 3 persona × 2 = 60 局）。

E1b · 到底是什么决定了人的排序——逐局阅读

指标层面的答案（false alarm、AQ）是相关性；要知道因果得看每一轮人是怎么排的。方法：为 31 位参与者各生成一份 dossier（三轮排序与评语、九局的完整时间线——assistant 每句话及其是否打断动作、若是警告则给出 app 用世界真值判的 verdict 与该 tick 的真实状态、人的每句话、人自己的犯错事件、装盘事件、结果），由 31 个独立的读者（subagent）通读，对每一轮写出决定性因素（从固定清单里选一个）、次要因素、赢家 / 输家的原因、逐字证据、评语与记录是否一致，以及一段参与者画像。读者不跑代码。原文在 study_collected_v2/dossiers/ 与 reading/。

结论一：决定人排序的是「有没有错怪我」，具体到一种话——「你放错了，把盘子倒掉重来」。57% 的轮次由 false accusation 决定；93 轮里 78 轮的证据引用了一条 dump / trash / start-over 指令。人几乎从不照做（读者在 31 份画像里反复写「ignored every dump order and won」），但会记住：

结论二：人分成两种，分界不是问卷。读者按画像把参与者分为「沉默是好事」（14 人：只要没说错就赢，一句不说也可以是第一）、「沉默是坏事」（8 人：奖励连续的、跟着自己动作走的 step-by-step 指导，安静的 assistant 即使做成也排最后）、混合（8 人）。两类人对错怪的态度一致（false accusation 在两类里都是第一决定因素），差别只在顶部怎么选：安静派把「没说错的那个」放第一，指导派把「话最多且跟得上的那个」放第一——apanagopoulou、gjn、Jianxu、kaili1 的赢家都是每局说 10–26 句的 assistant，准确率只决定倒数第一。问卷 q3（打断风格）与这个分型只有弱相关：q3=1「一步一步」的 7 人里 4 人是指导派、0 人是安静派；q3=3「非必要不打断」的 9 人里 6 人是安静派、1 人是指导派；q3=2 的 15 人三类都有。q2（报警激进度）与分型无关。

结论三：时间与成败不进入判断。读者在 31 份画像里反复记下同一件事：赢家的那局常常最慢（apanagopoulou R1 赢家 1.30x vs 输家 0.77x；gcowden R1 赢家 3.35x vs 输家 1.94x；Jianxu R2 赢家 2.06x），输家的那局常常最快（jiaruil5 R3 输家 0.79x，KevinC R2 输家 0.84x）；输掉的局（MklaCruz R1、cadossicarr R1、gjn R3）其 assistant 都没有因此垫底。这就是 S / TT / E 与排序无关的机制：人评的是对话体验，不是结局。

结论四：菜的难易与标签惯性是两个真实存在的噪声。29 轮的次要因素里有 recipe_difficulty——安静派的赢家几乎总是抽到 easy_nops（两样食材）那局的 assistant，因为那局最没有可说错的（dmosely、cadossicarr、RayTraylor、aastorri 的读者都指出了这个混淆）。四位参与者（RoyG、VickyLau69、gjn、kaili1）三轮给出完全相同的 A>B>C 顺序，读者判断为对标签形成的固定印象；hlz 明说「I remembered that Assistant A was annoying」把上一轮的怨气带进下一轮。5 轮读者判为「证据不能解释」，四轮是第三轮。

对 benchmark 的含义。rubric 里的 truthful（不说不真的话）与 economy 应当加权最高；一个 false alarm 的代价不是「一次误报」，而是「一次错怪」——尤其当它要求破坏性动作（倒盘）。detection 指标里的 precision 比 recall 更接近人的评价；而在真人不会自己犯错的自由游玩里，recall 根本没有用武之地。
