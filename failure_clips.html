CookSim 失败案例：assistant 没认出厨师的错误，也没帮厨师把菜做成

为 2026-09-21（周一）与 Silvio 的会议准备 · 5 个短片，均取自最近的真实 run · 生成于 2026-09-19 15:44 UTC

CookSim 是什么。CookSim 是一个模拟厨房。一位由 LLM 扮演的厨师（simulated human，按 persona 行事：新手、普通、老手）自己规划并做一道菜。engine 会在预先设计好的时刻接管厨师的手，让他犯一个真实的错误（放错食材、漏一步、忘关火、重复一步……），就像真人做饭时会出的错。被测的 AI assistant 只能看厨房的视频画面（左边俯视图，右边厨师第一人称视角），能随时开口说话，不能动手。它的任务有两个：(1) 认出错误，在错误造成后果之前说出来；(2) 帮厨师把菜做成，回答问题、给出正确的下一步。厨师每一道菜最后只有一次上菜机会，结果是 won（做对）、wrong_serve（上错了菜）或 burned（烧焦/起火）。

这一页展示什么。5 个 episode，assistant 都是前沿 API 模型（gpt-6-astra、gemini-3.1-pro、gpt-realtime-2.1、gemini-3.8-flash、gemini-3.1-flash-live）。每一个都满足三条：engine 安排的错误真实发生了（落到了盘子上或锅里）；assistant 没有正确地指出它（沉默、说了别的事、说错了东西，或者等错误落地之后才说）；最后菜失败了，而失败的原因正是这个没被指出的错误。多数片段里 assistant 还在厨师出错的同时给出了错误的信息或安慰（“盘子看起来没问题”）。

怎么看视频。蓝色字幕 = assistant，琥珀色字幕 = 厨师，声音是按字幕合成的语音。右上角是 tick（游戏时间的单位；视频里 1 tick ≈ 0.8 秒，说话时画面局部放慢，但不会停住）。每个片段是从完整影片里剪出来的：从错误发生前不久开始，到上菜的结果卡结束；中间的暗色卡片标出跳过的 tick 区间。所有影片都是对已保存记录的逐帧重放（replay），没有重新运行模型，也没有调用任何 API。

术语。下面的错误名称是 engine 的 error type：add_foreign = 盘子上多了一样不该有的东西；omit_subgoal = 漏放一样食材就上菜；repeat_step = 同一步做了两次；leave_unattended = 熟了的东西放在火上没人管，开始冒烟；forget_next_step = 厨师愣住，忘了下一步；search = 厨师在厨房里来回找东西（非致命）。grader 对 assistant 每句话的判定：valid = 在错误进行中正确点名；late = 错误落地之后才说对（不算检测）；wrong_name = 在错误进行中说了，但点名的是别的错误；false_alarm = 指控了一个不存在的错误。
