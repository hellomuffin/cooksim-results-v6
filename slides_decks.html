The detailed editing manual (geometry, video, house style) is docs/GOOGLE_SLIDES_HOWTO.md; this document points at it rather than repeating it.

2. How an agent accesses a deck

2.1 What works: the Composio CLI

Editing and reading native Google Slides from this machine goes through the Composio CLI, installed at ~/.composio/composio and already authorised for the account 1157430339@qq.com with the googleslides and googledrive toolkits active.

export PATH="$HOME/.composio:$PATH"
composio link googleslides --list        # expect: total 1, status ACTIVE
composio link googledrive --list

Verify a deck is reachable and writable before planning any edit:

composio execute GOOGLEDRIVE_GET_FILE_METADATA \
  -d '{"fileId":"1qwFEh0CVh5dkmF6t3eYVFeajgOR0PMNB-tkmGWwaLFc","fields":"id,name,mimeType,capabilities(canEdit)"}'

mimeType must be application/vnd.google-apps.presentation; capabilities.canEdit must be true.

Read a deck (always with a fields mask — a full presentation is enormous; large responses come back as {"storedInFile": true, "outputFilePath": ...} and the data is in that file):

composio execute GOOGLESLIDES_PRESENTATIONS_GET \
  -d '{"presentationId":"<ID>","fields":"slides(objectId,pageElements(objectId,size,transform,shape(text)))"}'

Write with one atomic batch of Slides API requests (any real request type works, including createImage, createVideo, updateVideoProperties, insertText, updatePageElementTransform):

composio execute GOOGLESLIDES_PRESENTATIONS_BATCH_UPDATE -d @batch.json
# batch.json = {"presentationId": "<ID>", "requests": [ ... ]}

If any request is invalid the whole batch is rejected and nothing is applied — check successful in the response, then render the slide and look (GOOGLESLIDES_GET_PAGE_THUMBNAIL2 returns a contentUrl; fetch it to a PNG).

A helper with the geometry and house style baked in is cook-bench-engine/tools/slides_deckkit.py (Deck with .txt(), .card(), .img(), .rm(), .dump()).

2.2 What needs a human

  • Re-linking a toolkit. If composio link <toolkit> --list prints total: 0, the OAuth consent flow is required and agents cannot complete it. Ask the presenter to run composio link googleslides --no-browser (same for googledrive) and hand back the URL result.
  • Making a Drive file public (GOOGLEDRIVE_CREATE_PERMISSION) is outward-facing and gated the same way.
  • Uploading a video larger than 5 MB needs GOOGLEDRIVE_RESUMABLE_UPLOAD; the plain upload has a hard 5 MB cap.

2.3 What does not work, so nobody tries it again

  • The Claude connectors for Google Drive / Gmail / Calendar available in this environment are read-oriented and need the user to authenticate in the session; there is no Slides connector. They can list and read Drive files after the user authenticates, but cannot edit a presentation.
  • WebFetch on a docs.google.com export URL (/export/txt, /export/pdf) redirects to googleusercontent.com and, for a public deck, works for reading — that is how the first session summarised the intern deck — but it cannot write.
  • The Slides API on a .pptx-backed Drive file (the second address above) fails; only native presentations can be edited.
  • Embedding a video from an arbitrary URL (a GitHub Pages .mp4) is impossible; Slides embeds video only from YouTube or Drive, and there is no loop property. The working rule: short clips (< ~15 s) as animated GIFs via createImage from the public cooksim-slides repo (Slides loops GIFs); long clips as .mp4 in Drive via createVideo with autoPlay and mute.

2.4 Traps that cost round trips (from the how-to, §6)

  1. A shape's rendered width is 3.28 in × scaleX — passing scaleX: 1 shrinks it to 3.28 inches; compute the scale from the size you want.
  2. Images cannot be resized by transform; delete and createImage again with an explicit size.
  3. deleteText on an empty shape is a 400 that kills the whole batch.
  4. objectId must be at least 5 characters.
  5. createSlide with predefinedLayout: 'BLANK' fails on this master; use slideLayoutReference: {layoutId: 'p12'}.
  6. Inserted text inherits the target shape's bullets; follow insertText with deleteParagraphBullets.
  7. Bulk font changes hit titles too; filter by placeholder type or size.
  8. GOOGLEDRIVE_GET_FILE_METADATA takes fileId; GOOGLEDRIVE_FIND_FILE takes q.
  9. successful: true is not proof; render the page.

2.5 Coordination with the presenter

The presenter edits the live deck in the browser while agents write to it. Read a slide immediately before changing it; never re-add elements you do not find (they were deleted on purpose); keep edits surgical and scoped to the slide you were asked about — rewriting a slide wholesale silently discards manual edits.

3. Quick start for a fresh agent

  1. export PATH="$HOME/.composio:$PATH" and confirm both toolkits are ACTIVE (§2.1); if not, stop and ask the human to re-link.
  2. Confirm the target is the native deck 1qwFEh0CVh5dkmF6t3eYVFeajgOR0PMNB-tkmGWwaLFc and is writable.
  3. Read only the slide(s) you will touch with a tight fields mask.
  4. Build one batch of requests using tools/slides_deckkit.py; apply; render the thumbnail; look.
  5. Media: GIF for short clips (recipe in the how-to §4), Drive .mp4 for long ones; publish GIFs to hellomuffin/cooksim-slides and keep the manifest.json namespaces.
  6. Prose goes in speaker notes; the slide carries few words at large size.
