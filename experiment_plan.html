01 / Main results

Does assistance improve task completion?

All three environments · full assistant roster + silent baseline · three runs

Rank assistants by task success and measure how much each helps relative to no assistance.

Execution agent delivers

  • Run the frozen case/persona suite with measured assistant latency; document ScreenSim’s actual timing policy.
  • Return episode outcomes and raw metric components, complete action/conversation traces, and scheduled versus actually triggered events.
  • Provide per-model/per-environment results, paired gains over silence, difficulty/persona breakdowns, and a complete failure/retry log.

My post-analysis

  • Estimate success gains over silence with paired uncertainty; show per-environment rankings before any overall average.
  • Explain differences using efficiency, prevention/recovery, QA, and proactive alerts.
  • Check whether gains vary with difficulty or persona, and whether event exposure differs between assistants.
Paper deliverableMain comparison table + success-gain plot

Watch for: Benefit is measured within the controlled user harness, not directly in unrestricted real-human use.

02 / Main results

Where does assistance break down?

Reuse experiment 01 · round-level rubric grading

Identify capability weaknesses rather than producing only another overall model score.

Execution agent delivers

  • Return every rubric item’s verdict, applicability, evidence, judge identity, and engine override for each round.
  • Use a common judge panel across assistant models; retain separate judge outputs and a stratified human audit.
  • Map rubric items to grounding, temporal understanding, actionable guidance, interaction management, and user adaptation; link examples to frames and traces.

My post-analysis

  • Build a capability-level heatmap with applicable-round denominators and episode-balanced summaries.
  • Measure judge disagreement and distinguish hard failures from softer quality penalties.
  • Trace recurring failures to available evidence; propose focused memory or speaking-policy ablations before making causal claims.
Paper deliverableCapability heatmap + a few evidence-backed failure examples

Watch for: Silence does not create a rubric round. Missed obligations must remain visible in event metrics; judge scores are not human satisfaction.

03 / Main results

Are the scores and rankings reliable?

Reuse experiment 01’s three runs · no separate benchmark sweep

Separate consistent model differences from stochastic rollout variation.

Execution agent delivers

  • Return a task × persona × model × repetition coverage matrix and every per-run metric.
  • Keep raw scores, cluster IDs, missing-run explanations, retry history, and supported seed settings.
  • Provide paired comparison and resampling scripts, seeds, unadjusted/adjusted p-values, and ranking-stability outputs.

My post-analysis

  • Estimate paired confidence intervals by resampling base tasks while retaining their personas and repetitions.
  • Report each run and average single-attempt performance; test prespecified contrasts with multiplicity correction.
  • Show ranking uncertainty and identify comparisons that remain inconclusive.
Paper deliverableShort reliability paragraph + uncertainty/ranking appendix

Watch for: Three attempts averaged are not pass@3. Conversation rounds and repeated personas are not independent tasks.

04 / Validation & ablations

When does delayed guidance stop helping?

CookSim primary · VHSim where meaningful · ScreenSim not a primary latency ablation

Measure both deployment-time latency costs and controlled sensitivity to delivery delay.

Execution agent delivers

  • Run fresh, paired zero-delay and measured-delay rollouts; keep other settings fixed.
  • On a representative model subset, test common fixed delays selected from pilot observations.
  • Record observation cutoff, call start/end, delivery tick, charged delay/cap, hardware, warm-up and contention, plus validity at generation and delivery.

My post-analysis

  • Compare success, prevention, recovery, QA, and rankings between timing conditions.
  • Attribute losses to stale advice, already-completed steps, missed commitment/alert windows, or newly arriving questions.
  • Use fixed-delay curves to separate sensitivity to delay from differences in model/provider speed.
Paper deliverableZero-versus-measured ranking plot + delay-response curves

Watch for: Time-shifting a recorded conversation is not a closed-loop experiment. ScreenSim’s actual scheduling still needs to be documented.

05 / Human validation

Which rankings reflect human preference?

Existing collection first · no new recruitment

Test metric agreement on real-human episodes separately from simulation-to-human ranking transfer.

Execution agent delivers

  • Inventory and deduplicate actual exports; recover deployed versions, tasks, model identities, encounter order, blind labels, and ranking scope.
  • Return pseudonymous participants, exposures, rankings/ties, episode metrics, and metric eligibility/coverage.
  • For any exploratory fitted metric combination, return participant-held-out folds, weights, predictions, and null baselines.

My post-analysis

  • Compare metrics against within-person preferences over the exact block each ranking describes.
  • Cluster uncertainty by participant; account for unequal model exposure and disconnected comparisons.
  • Separately test whether matched simulated-benchmark rankings transfer to human preferences; inspect learning and order effects.
Paper deliverablePreference-agreement table + simulation-to-human transfer analysis

Watch for: Undefined scores are not zero. Do not recycle old fitted weights or interpret later assisted play versus earlier solo play as randomized evidence.

06 / Human validation

How closely does the simulated user resemble people?

Existing human traces + matched, uninjected simulated free play

Measure behavioral similarities and limitations in execution, conversation, and response to guidance.

Execution agent delivers

  • Return matched cohorts with task, assistant, version, pacing and experience strata; disclose control-interface and ASR differences.
  • Extract success/progress, spontaneous errors, action order, concurrency, recovery, pauses, and food left on heat.
  • Annotate speech frequency, reply probability, questions, disagreement, next-step narration, and guidance uptake; retain evidence and spontaneous/forced/instructed labels.

My post-analysis

  • Compare task-conditioned distributions, first versus later attempts, and human-to-human variability.
  • Distinguish verbal agreement from actual action and reasonable rejection from noncompliance.
  • Characterize mismatches with uncertainty and examples; compare conversational function and style, not exact wording.
Paper deliverableHuman-versus-simulated behavior profile + limitations

Watch for: Masking forced ticks does not undo their downstream effects. Primary realism comparisons need uninjected episodes.

07 / Validation & ablations

Is the choice of simulated-user model defensible?

Original probes + human-grounded fidelity + assistant × user-model cross-test

Separate harness correctness, resemblance to people, and robustness of assistant rankings.

Execution agent delivers

  • Re-audit the original grounding, control-consistency and persona probes; test identical interventions from matched states, including incorrect guidance.
  • Compare the current backbone, a stronger same-family candidate and an independent family against the matched human-data measures.
  • Cross representative assistants with candidate user models on a balanced subset, with three repeats and a silent baseline for each backbone; return selection splits and all raw probe/rollout outputs.

My post-analysis

  • Keep operational capability and human fidelity separate; inspect excessive obedience, verbosity and unnatural self-reporting.
  • Measure assistant-by-user-model interactions, paired gains, event exposure, and uncertainty in ranking reversals.
  • Connect CookSim ranking sensitivity to human fidelity; disclose prior human-data reuse and test selected configurations on held-out participants where possible.
Paper deliverableCapability-versus-fidelity plot + ranking-sensitivity heatmap

Watch for: The strongest task solver is not automatically the most realistic human simulator. CookSim human evidence does not validate every domain.

Required from every agent

Raw evidence, not just a leaderboard

Each deliverable must trace back to immutable source records. Large or private artifacts can remain outside the paper repository, linked by a checksummed manifest.

Configuration
Engine and suite hashes, exact model IDs, prompts, rubric versions, observations, seeds, timing policies, hardware and concurrency.
Episodes & events
Outcomes, metric components and denominators, scheduled/reached/fired events, actual timestamps, and reasons for missing values.
Interaction traces
Observations, state references, conversations, action queues, executed/rejected actions, and provenance of forced versus spontaneous behavior.
Failures & retries
Every attempted run, failure reason, retry, exclusion and superseding record. No selective favorable reruns.
Reproduction
Analysis scripts, machine-readable tables, intervals, figure sources, and findings linked to evidence.

Privacy: keep identifiable study data, recordings, participant mappings and credentials out of the paper repository. Undefined metrics stay missing, not zero.
